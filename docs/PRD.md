```
                 ┌──────────────────────▼──────────────────────┐

                 │  搜索 / 书籍信息 / 书评 / 书架 / 笔记 / 统计 / 推荐 │
                 └──────────────────────────────────────────────┘
                                        │ deepLink 回跳
                                   微信读书 App
```

架构要点：

- **三层解耦**：前端只做渲染；服务端持有决策引擎、整理引擎、同步层；微信读书侧只读。
- **数据双源**：个人数据（划线/想法/书架）经同步层落 SQLite 本地库；书评/书籍信息走缓存层按 TTL 复用。
- **key 流向**：用户 key 仅存在于服务端会话内存，随请求转发，永不落盘。
- **无后台任务**：所有网关调用发生在用户会话内。

## 1. 背景与机会

### 1.1 微信读书的现状缺口

微信读书已内置 AI问书（读中概念问答）、AI大纲（通用章节摘要）和 ima 联动（书架整理），官方持续迭代读中 AI 能力。**本产品不做读中**。真实存在且官方未解决的缺口在两端：

- **读前决策**：一本书几百条书评，好评刷屏差评零散，用户要翻很久才能判断"适不适合**此刻的我**"；评分只有均值，没有人群维度和预期匹配视角。官方推荐回答"你喜欢什么"，不回答"你现在该不该读这本"。
- **读后痕迹**：划线困在 App 内，读完就忘，跨书观点无法串联。用户靠 Chrome 插件往 Notion/Obsidian 搬运维生，官方年度报告被集中吐槽"策划能力差"。

### 1.2 机会窗口

微信读书开放了 Agent API Gateway（BYOK，用户自带 API Key，数据按个人身份隔离），第三方首次能拿到**个人级**阅读数据：书架、划线、想法、书评、阅读统计、逐书阅读时长。官方 AI 的输出对象是"书"（人人相同），本产品的输出对象是"我"——这是结构性差异，不靠 prompt 能追平。

### 1.3 定位

**读书选择器 + 阅读痕迹作品化工具**，主线三段：

```
读前：我该不该读？（MVP）→ 读后：我留下了什么？（MVP）→ 表达：我如何讲述？（二期）
```

价值主张一句话：**把"评分 82%"翻译成"这本书配不配得上你此刻的目标、时间和已读背景"；把划线从收藏变成作品。**

## 2. 用户与场景

### 2.1 目标用户

微信读书重度用户：有划线/想法习惯（笔记是产品价值的前提）、书架"想读"堆积、读完的书留不下东西。**明确排除**：无笔记习惯的轻度读者（读后模块无素材）、听书主导用户（速度基线与痕迹能力受限）。

### 2.2 核心场景

**场景一：选书决策。** 用户输入"我想理解组织为什么失灵，但不想读太学术的书"。系统解析目标（解决具体问题 + 低门槛约束），扩展搜索词出 5 本候选，用户圈 3 本，生成三张决策卡：每张给出"现在读 / 放入待读 / 排除"的可解释判定，附预计时长（按用户自己的阅读速度算）、好评差评分歧主题（挂原文引文）、与已读书的补充/重复/反驳关系。用户点"现在读"跳微信读书开始读，决策留档。

**场景二：弃读回顾。** 某书读到 12% 放下了。回顾的框架不是"总结这本书"，而是"为什么停 + 已经带走了什么"：那 8 条划线说明当时被什么吸引，进度轨迹说明在哪里失去耐心。弃读不再只有负罪感。

**场景三：跨书整理。** 用户提问"权力如何影响组织"，系统从全部划线和想法里找出跨书主题、分歧与演变——"你在《X》里划的这三条和《Y》里那条想法方向相反"，整理成观点—证据—反思卡片组，用户编辑确认后导出 Markdown。

## 3. 产品原则（三条，全局生效）

| 原则 | 内容 | 执行细则 |
|---|---|---|
| **P1 证据规范** | 无证据不出结论 | 三级证据：直接引文 / 归纳（附样本量）/ 推断（附依据），措辞随级别降级。书评每档抽样 20 条，`max(2, ⌈15%×抽样数⌉)` 条同向才成"主题"，每档主题 3-6 个，展示口径为"20 条抽样差评中 5 条提及"。证据不足的点进"存疑区"，不硬编 |
| **P2 只读边界** | 对微信读书零写入 | 所有状态（待读/排除/草稿/档案）在本产品侧；deepLink 是唯一回跳方式；API Key 只在会话内存、不落盘不写日志 |
| **P3 确认分级** | 分界线是"对外与否" | 对内（决策建议、复盘、整理草稿）不确认；对外（分享卡、导出）一步预览确认后生成 |

### F1.1 目标解析与追问

| 项 | 内容 |
|---|---|
| 序号 | F1.1 |
| 描述 | 把用户一句话解析为结构化目标；目标含糊时追问一轮 |
| 输入 | 用户自由文本（主题式 / 书目式） |
| 输出 | `{goal_type, topic, constraints}`；触发时输出追问 chips |
| 依赖 | LLM；无网关调用 |
| 优先级 | P0 |

**布局与逻辑**

- 目标解析
  - 结构化输出 `{goal_type, topic, constraints}`
  - goal_type 六类，控制整张卡的权重与特殊行为
    - 解决具体问题：内容匹配看方法/工具密度；"不解决实际问题"类差评权重最高
    - 系统入门：看前置知识链；常触发"先读入门书"替代方案
    - 找反方观点：与已读观点关系为主；"反驳"类个人关联权重最高
    - 消遣放松：看节奏与易读性；阅读成本权重调低
    - 跟上话题：讨论度与时效优先；评分人数权重调高
    - 重读：跳过防重复；个人关联改为"上次读到哪、为何弃"
  - constraints 可选约束
    - time_budget：每周小时数 / 总预算
    - difficulty：如"不想太学术"
    - deadline：影响 read_now 判定
- 追问逻辑
  - 触发条件：goal_type 无法判定（典型输入"这书怎么样"）
  - 形式：可点选项 chips（解决具体问题 / 系统了解 / 随便看看…），不问开放式问题
  - 上限：最多一轮
- 入口分支
  - 主题式（"组织为什么失灵"）→ 进 F1.2
  - 书目式（"《X》值得读吗"）→ 跳过 F1.2，直接 F1.3 单本卡
  - 书架式（想读堆批量）→ 二期

### F1.2 候选圈定（5 选 3）

| 项 | 内容 |
|---|---|
| 序号 | F1.2 |
| 描述 | 关键词扩展搜索 + 相似书 + 粗筛，产出 5 本候选供用户圈定 |
| 输入 | topic + constraints + 个人背景（书架/已读清单） |
| 输出 | 5 本候选列表（每本带四项信息），用户圈定 1-3 本 |
| 依赖 | 书城搜索、相似书推荐、书架同步、书籍缓存 |
| 优先级 | P0 |

**布局与逻辑**

- 候选生成管道
  - 关键词扩展：LLM 由 topic 扩展 3-5 个搜索词（同义/下位词，如 组织失灵 → 组织失效 / 大公司病 / 官僚制）
  - 来源组合：书城搜索为主，相似书推荐补充
  - 粗筛规则
    - 评分人数 ≥ 下限（保证书评样本可用）
    - 书架去重：已读剔除（goal=重读时除外）
    - 命中本产品"待读清单"的标注提示
- 候选展示（每本四项信息）
  - 书名 + 评分
  - 一行内容预告
  - 来源标签（搜索 / 相似 / 书单）
  - 去重提示（"与你在读的《X》同主题"）
- 用户操作
  - 圈选：默认预勾选匹配预估最高的 3 本，可改选、可少选（1-2 本直接生成）
  - 换一批：取粗筛列表的下一组 5 本
  - 换个说法：返回修改主题 / 约束
- 例外处理
  - 书目式入口跳过本步
  - 搜索结果不足 5 本：有几本给几本，并说明原因

### F1.3 决策卡生成

| 项 | 内容 |
|---|---|
| 序号 | F1.3 |
| 描述 | 每本候选生成六块信息的可解释决策卡（字段级定义见 `decision-card-spec.md`） |
| 输入 | bookId + goal + constraints + 个人背景（速度基线/已读/划线主题样本） |
| 输出 | 结构化决策卡 JSON + 渲染卡片；多本时附横向对比行 |
| 依赖 | 书籍信息、章节目录、书评×3档、热门划线、书评缓存（TTL 内免拉） |
| 优先级 | P0 |

**布局与逻辑**

- 六块信息结构
  - ① 可解释结论：verdict（read_now/shelve/skip）+ 置信度 + ≤30 字结论 + 暂缓触发条件（shelve 时必填）
  - ② 内容匹配：核心问题（≤40字）/ 论证方式 / 匹配分 1-5 / 错配警告
  - ③ 阅读成本：预计时长（个人速度）+ 日历换算（"每周3小时约2周"）+ 门槛与前置知识 + 译本/版本提醒
  - ④ 评论分歧：好评/差评主题（挂引文与星级）、争议焦点、资深会员推荐率、好友点评数
  - ⑤ 个人关联：与已读的补充/重复/反驳/前置关系 + "已在你的书单" + "曾读到 12% 弃读"召回
  - ⑥ 替代方案：verdict 非读时必填，1-2 本 + 一句话理由
- 首屏与折叠
  - 首屏三件套：结论 + 预计时长 + 最大分歧
  - 其余分块折叠，逐块展开
- 证据链要求（P1）
  - 每个结论可点开看证据引文（书评原文 / 划线 / 接口字段）
  - 归纳类主题标注样本量；推断类标注依据
  - 证据不足的点进"存疑区"明示
- 剧透相关区块按 F1.5 策略处理

### F1.4 判定引擎（硬闸门 + LLM 裁量）

| 项 | 内容 |
|---|---|
| 序号 | F1.4 |
| 描述 | 规则做上下限闸门，LLM 在闸门范围内裁量，置信度按证据一致性分级 |
| 输入 | F1.3 六块证据 |
| 输出 | verdict + 结论 + 触发条件 + 置信度 |
| 依赖 | F1.1-F1.3 |
| 优先级 | P0 |

**布局与逻辑**

- 硬闸门（一票上限）
  - 内容与目标严重错配 → verdict 上限 shelve
  - 预计时长 >3× time_budget → 上限 shelve（trigger="时间宽裕时"）
  - 与已读重复度高 → 上限 shelve
- 保底闸门（一票下限）
  - 匹配≥4 且成本合预算且无主题级负面 → 保底可 read_now
- LLM 裁量
  - 作用域：闸门允许的集合内做权衡
  - 输出：verdict + one_liner + shelve_trigger
- 置信度分级
  - high：三块证据（内容匹配/评论分歧/个人关联）方向一致且样本足
  - medium：有冲突信号但主导方向明确
  - low：关键块证据不足 → 卡片必须明示"低置信判断"
- 可回测性
  - decision_record 记录命中的闸门与裁量结果
  - 定位问题：闸门错改规则，裁量错调 prompt
  - 二期复盘卡据此统计判定准确率

### F1.5 剧透控制

| 项 | 内容 |
|---|---|
| 序号 | F1.5 |
| 描述 | 按书籍类型自适应的剧透防护 + 用户全局偏好 |
| 输入 | 书籍分类、热门划线候选、用户偏好档位 |
| 输出 | 过滤后的内容样本区块 |
| 优先级 | P1 |

**布局与逻辑**

- 分类自适应
  - 小说/文学类：内容样本区仅展示无剧透描述（核心问题/形式/节奏），热门划线一律不展示
  - 社科/非虚构：金句型划线默认展示，结论剧透型折叠
- 判别启发式
  - 情节型：人名密集 / 章节位置靠后
  - 结论型：直接泄露全书最终论点的划线
- 全局偏好
  - 三档：无剧透 / 轻 / 全，设置页可改，默认无剧透

### F1.6 决策动作与档案

| 项 | 内容 |
|---|---|
| 序号 | F1.6 |
| 描述 | 三动作 + 决策完整落库（MVP 只落数据，复盘卡二期） |
| 输入 | 用户对卡片的动作 |
| 输出 | 待读清单变更、decision_record 落库、deepLink 跳转 |
| 优先级 | P0 |

**布局与逻辑**

- 三个动作
  - 现在读：deepLink 跳微信读书
  - 放入待读：写入本产品清单，可附触发条件（"读完《X》后"）
  - 排除：落库 + 一句理由
- 档案内容
  - 卡片完整 JSON 快照 / verdict / 用户动作 / 动作时间 / 命中的闸门
- 边界
  - 对微信读书零写入，待读清单仅本产品可见
  - 允许对历史决策改判（改判留痕）

### F2.1 单书回顾（含弃读）

| 项 | 内容 |
|---|---|
| 序号 | F2.1 |
| 描述 | 整理"我和这本书发生了什么"，支持读完与弃读两种框架 |
| 输入 | bookId（用户选书或"最近读完/弃读"快捷入口） |
| 输出 | 单书回顾结构化草稿（F2.3 的札记原料） |
| 依赖 | 本地库：划线 / 想法 / 我的书评 / 阅读轨迹 |
| 优先级 | P0 |

**布局与逻辑**

#### 4.7.4 三维书架技术方案（Three.js，参照 ThreeUI CompleteShelfLandingPage）

- 渲染
  - Three.js（r165+），`RoundedBoxGeometry` 书体 + `MeshPhysicalMaterial`（书页/装帧）+ `MeshStandardMaterial`（木质搁板）+ `RoomEnvironment` 环境光照
  - 封面：服务端代理取封面图 → Canvas 绘制 → 叠加边缘明暗渐变 → `THREE.CanvasTexture`（SRGB / mipmap / anisotropy）；书脊 = 封面主色纯色 + 书名
- 主题色系统（"滑动换背景"的实现）
  - **同步时预计算**：F3.1/F3.2 拉封面 → 缩至 32×48 量化取主色 → 推导 10 键调色板（paper/paperDeep/paperPale/ink/inkSoft/shelf/shelfDark/light/fill/accent）→ 存 `book_cache`
  - **渲染时零开销**：焦点书切换 = CSS 变量批量 `setProperty` + 灯光色 `THREE.Color` 过渡，720ms CSS transition；不达标情况：封面缺失时回退到按书名哈希生成的稳定色
- 封面代理（硬性依赖）
  - 微信读书封面 CDN 无 CORS 头，浏览器直取会污染 canvas、无法灌 WebGL 纹理；由服务端代理缓存封面图（与网关转发共用 P2 代理层），同时服务主色提取与前端加载
- 性能与大书架
  - 书架可达上百本：仅实例化焦点 ±N 本网格，其余虚拟化
  - 封面纹理 LRU 缓存 + 预取焦点相邻 2 本（滚轮顺序移动）
  - 首帧预算：书架可交互 ≤3 秒（封面渐进加载，先主色书脊后封面）
- 交互（沿用参考）
  - 滚轮（空闲 0.14s 后吸附整数位）/ 左右箭头 / 点击选中居中
  - 拖拽封面 / 双击 = 打开书籍详情页（本期预留入口，页面后议）
  - 背景微幅拖拽旋转（OrbitControls，限制角度）
- 降级
  - `prefers-reduced-motion` 或 WebGL 不可用：退化为静态封面网格 + 主题色仍然跟随（纯 CSS）
- 参考源码
  - `references/complete-shelf-v2.html`（ThreeUI CompleteShelfLandingPage，已存档供开发对照）

## 6. 成功指标（个人工具，重质量轻规模）

| 指标 | 定义 | 目标 |
|---|---|---|
| 决策卡动作率 | 出卡后产生三动作之一的比例 | ≥70% |
| 判定回测准确率 | 用户实际读完（弃读）与 read_now（skip）判定的一致性 | 二期复盘卡上线后统计，≥60% 起评 |
| 时长预测误差 | \|预测 − 实际累计时长\| / 实际，对已读完书回测 | ≤40% |
| 札记编辑率 | 生成草稿被编辑的比例 | 30%-80%（过高说明草稿差，过低说明没人在意） |
| 划线复用率 | 每月被整理/导出引用的划线占比 | 环比上升 |

## 7. 里程碑

- **MVP**：F1（选书决策页）+ F2（读后作品页）+ F3（数据与账户）。
- **二期**：复盘卡（预期 vs 现实，读决策档案回测）、自画像（问题地图/思想轨迹卡/阅读信；允许适度解读——边界见 8.1）、Notion/Obsidian 集成、自动聚类主题建议、书友对照层（视网关接口演进）、书架瘦身批量卡。
- **待验证项**：`/_list` 终验网关接口全集（需 API Key）；网关调用频率限制实测；浏览器直连 CORS（默认走服务端转发，不受影响）。

## 8. 风险与对策

### 8.1 自画像"适度解读"的边界（二期执行，现在立规）

允许解读性表述（"你这半年似乎在回避 X 类书"），但三条底线：①每条解读必须挂事实锚点（后附可验证依据：书架构成、弃读记录）；②不使用封闭式人格标签（"你是 XX 型读者"禁止）；③用户可标记"不准"并将其剔除出画像。

### 8.2 外部风险

| 风险 | 对策 |
|---|---|
| 网关频率限制未知 | 缓存层已设计；上线前压测；控制并发 ≤8 |
| 官方 AI 扩展到选书/整理 | 护城河是个人决策档案闭环（历史判定可回测）+ 跨书个人痕迹，官方通用功能难以覆盖 |
| 书评抽样代表性（每档 20 条） | 展示口径明示抽样数与快照日期，P1 措辞降级 |
| 点赞接口文档核查与实际不符 | API Key 可用后 `/_list` 终验，一分钟完成 |
